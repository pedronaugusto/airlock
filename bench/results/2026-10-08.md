# 2026-10-08: macOS and local Linux

Zig 0.17.0, ReleaseFast. macOS 26.2 (25C56), ARM64 Mac15,8, 16 logical CPUs, internal Apple SSD, APFS Data volume. Linux: the local Lima `bench` VM, Ubuntu 24.04.5, ARM64, kernel 6.8.0-142, 8 vCPUs, `kernel.io_uring_disabled = 0`. The repository was copied into the VM; its home is on `/dev/vda1`, ext4. XFS was measured on a fresh 2 GiB loop image backed by that ext4 virtual disk. These Linux results describe the requested local VM, not a physical NVMe release pass. Both drivers use std.Io.Threaded; raw syncs do not submit io_uring operations. No Windows timing was taken; CI compiles its benchmark code.

The full matrices contain 109 macOS rows and 155 rows for each Linux filesystem, including count rows. Repetitions alternate production source from main `2baacc5866aeb9212d8763df54a91fa529be9f82` and this change, using the same common timed workloads (the old source cannot call the new hook). Three repeats were taken for sync, 4 KiB data replace, 100-file 4 KiB batches and append/migration comparisons. Throughput comparisons below select the best whole run, not the best individual sample. Full-matrix latency is from one run; small batch sample counts are not strong p99 evidence.

## Acceptance against the design

| Target | Measured result | Verdict |
|---|---|---|
| macOS N=100 batch ≥10× reopened-path durability | 8,727.4 vs 9,358.4 files/s; 0.93× | **Missed** |
| macOS N=100 batch ≥10× write/copy then flush each, cloning off | 8,727.4 vs 201.8 files/s; 43.25× | Met for this loop shape |
| Exact barrier counts | macOS data replace: 1 B + 1 F; barrier off: 2 F. N=100 batch + one directory: 101 W + 1 F, plus 1 B with renames. Linux replace: 2 F; batch: N file F + distinct directory F. | Met; deterministic tests gate these on all three OSes |
| Linux concurrent data syncs beat sequential, writing handles | linux-ext4: N=10: 2.61×, N=100: 2.36×, N=1000: 2.62× | Met on these VM volumes |
| Linux concurrent data syncs beat sequential, writing handles | linux-xfs: N=10: 2.79×, N=100: 4.22×, N=1000: 3.82× | Met on these VM volumes |

The macOS reopened-path result is a real target miss, not a 10× claim. In this workload all files are written and closed before reopening them for sync. The kernel coalesces dirty writeout and later full-sync calls can be cheap; counting N full-sync calls does not establish N physical cache drains. Batching retains the writing handles (and their error state) and identifies every volume, as correctness requires. This leaves it 6.7% below that baseline here despite the smaller flush-call count. The flush-each row instead syncs each still-dirty writing handle immediately, matching the non-cloning backup loop shape; it is a workload baseline, not a verbatim copy of chronicle.

Path rows are a separate contract: reopening can miss writeback errors already reported to another descriptor. They are retained in the complete matrix rather than treated as equal to syncs on writing handles. Not every small path row improves at p16. The default remains 16: writing-handle concurrency wins on both measured filesystems, and a nested virtual XFS image is insufficient evidence for tuning the package for physical storage.

The lower p16 data-batch samples are disclosed: −5.4% on macOS and −7.3% on ext4. The three-run throughput ranges overlap (macOS before 7,646–8,760 vs current 7,804–8,284; ext4 before 9,174–16,747 vs current 8,171–15,528 files/s). These samples cannot establish a universal absence of measurable regression. Sync, overwrite and append are near parity; full batch results are mixed. Durability counts are unchanged. ReleaseFast inspection of `syncFile(..., .{})` on macOS eliminates executor dispatch entirely and reduces its stack frame from 112 to 96 bytes. A runtime-selected optional hook necessarily requires a null check; unused hooks create no executor, job, thread, queue or allocation. No performance threshold gates CI.

## Evidence and reproduction

`zig build test -Dtest-filter="blocking hook"` passes on native macOS and the VM (the Darwin-only errno test skips on Linux). It checks real worker execution, no jobs at none/ordered-directory, cancellation before and after publication, seam refusal/interruption/final errors, kept names, fences, name operations and concurrent batches. The Darwin test deliberately overwrites caller errno after the worker finishes and verifies the syscall result was captured on the worker. Existing level, barrier-count and selected exhaustive fault-sweep tests pass; lint, native check and Windows cross-compilation pass. Hosted fast and merge tiers run the remaining suite.

`zig build bench` records the complete matrix. For repeated common rows, run the installed binary with `probe/sync-data`, `replace/data/4k`, `batch/100/4k/` and `ab/`, alternating original/current executables three times on the same selected parent. Each driver owns a fresh random child per invocation and a fresh directory per row. The old source uses the current common workload driver with added-only hook calls removed.
