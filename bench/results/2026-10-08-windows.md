## Workloads and units

All 109 emitted records are retained: 97 timing rows, 10 separate count rows
and 2 explicit unsupported rows. No rows were selected out of the artifact.
The full suite covers raw Windows flush primitives; dirty 4 KiB file and
directory probes; new/overwrite publishes at 4 KiB and 1 MiB at every level;
1/10/100/1000-file batches at 4/64 KiB using pending renames, writing handles
or reopened paths; name operations, pruning, append/migration workloads, and
inline versus application-supplied executor calls. The Windows driver emits
p1 and p16 batch configurations; p4 and p64 are Linux-only configurations.

`ops` is the number of timed samples. `p50_us`/`p99_us` are per-call or
per-batch latency in microseconds. `per_second` counts operations, files for
batch rows, or removed temps for pruning. Probes take 1000 samples; publishes
200 at 4 KiB or 50 at 1 MiB; regular batches 20 for N < 100 and 3 otherwise.
The JSONL records the sample count of every timing row, including hook and
migration rows with their own counts. Each row is one run, with no interleaved
before/after production change.

Probes dirty the file or directory before starting each timer. Publishes and
batches include creation, writing, commit and handle cleanup. Count collection
runs separately from timing. W/B/F and `raw_calls` describe primitive/seam
calls, not physical device cache drains. Where `counts_available` is false,
zero count fields mean uninstrumented; they are not measured zero syscalls.
Count-only records have no latency or sample estimates.

## Limitations and unsupported work

- `ops/sym-link` and `counts/sym-link` emit `skipped: true` with the exact
  reason: `airlock.symLink` returns `OperationUnsupported` on Windows. They
  have no success counts or invented zero latency. The former benchmark's
  Windows no-op is no longer reported as a successful timed operation.
- `airlock-macos-batch` emits no records on Windows because it returns before
  its Darwin-only strategies. Those primitives cannot be timed on this runner.
- No raw primitive refused in this run. On refusal the driver emits the
  refusal record without a latency; it does not convert it into a success.
- Three-sample large-batch rows do not establish tail latency. Shared CPU,
  virtual filesystem/device layers, caching and other tenants can affect
  every number; repetitions on controlled physical hardware remain separate
  work. Reopened-path rows have the driver-documented writeback-error limitation.
- The preceding [run 37816096643](https://github.com/pedronaugusto/airlock/actions/runs/37816096643)
  emitted no rows: a fresh lazy-dependency configuration rejected the optional
  `ci-lint` option before benchmark execution. This successful run uses the
  supported standard command without that unrelated option.

These observations have no target verdict and do not change the durability
contract. Ordinary CI continues to compile and smoke-run benchmarks without
collecting timings; measurements require the manual opt-in dispatch.
